# Sustainability and ecosystem governance

Searchright is designed for a sole-maintainer-compatible start without making
one person a permanent single point of failure.

## Maintenance contract

- Version contracts before implementations.
- Publish deprecation windows and migration recipes.
- Separate security response from ordinary feature triage.
- Record standards surveillance and licence changes.
- Require evidence receipts for support and registry claims.
- Keep adapters replaceable and the stable kernel small.

## Succession and bus-factor controls

Architecture decisions, release procedures, threat models, schemas, fixtures and
track evidence are repository artefacts. Releases should be reproducible by a
fresh maintainer from a tagged commit. Signing and registry credentials remain
outside the repository and need documented recovery/rotation procedures.

## Community path

The early project accepts contract, fixture, provider, documentation and
methodological contributions. Governance expansion is triggered by sustained
external contribution or institutional adoption, not by premature committees.

## Funding and conflicts

Future grants, commercial support, database-provider relationships and paid
integration work must be disclosed with their effect on roadmap priority and
benchmark independence.

The required observation categories are recorded in
`evaluation/external-evaluation.json`. The source contract remains
`prepared_not_observed`; repository documentation and a static check do not
demonstrate maintenance history, standards surveillance or succession practice.
