# Portfolio reuse and dataset routing

**Inspected: 7 November 2026. Status: planning evidence, not executed integration.**

Searchright should consume the existing archive, extraction, citation and publication systems through versioned contracts. It should not build a second harvester, bibliography engine or dataset catalogue. The ownership boundaries in [estate integration](../estate-integration.md) remain authoritative: neutral provider execution belongs to `evidence-search-core`; Searchright owns review state, deduplication, report/study linkage and search orchestration.

The primary links below identify observed source and dataset-card evidence. Repository descriptions do not establish runtime compatibility, current corpus coverage or scientific validity. These observations do not update existing integration pins automatically.

## Route future datasets through the existing systems

1. **Identify ownership in GitHub and the estate registry.** Put Searchright schemas, transforms, evaluation definitions, small synthetic fixtures and receipt manifests in this repository. Route new archival source families to their existing producer repository. Reuse a canonical HF dataset where its scope fits; otherwise register a distinct derivative or benchmark linked to its parents.

2. **Build from pinned inputs.** Record producer commit, full HF revision, upstream authority/edition, object paths and hashes, transformation version, source-specific rights, acquisition time and declared coverage. Preserve raw, extracted and model-inferred layers separately. Reconcile stale registry/card disagreements before use.

3. **Admit evidence explicitly.** Validate object availability and hashes, capture state, schema and permitted use. Exclude dry runs, synthetic fixtures and metadata-only placeholders from empirical denominators. Count catalogued records, captured objects, searchable documents, retrieved reports and linked studies separately.

4. **Publish versioned data to HF.** Reuse existing publisher components after compatibility checks; keep large public payloads out of GitHub. Candidate Searchright products include retrieval judgements, deduplication/study-linkage benchmarks, extraction evaluations and redacted agent-run traces. Dataset cards must identify intended use, split construction, annotation method, uncertainty, exclusions and source licences. Keep sealed evaluation labels outside development prompts and public training artefacts.

5. **Verify and reconcile.** An authorised publication must return the exact HF revision; independently reload its intended assets/configuration and verify hashes. Update the existing estate registry and link the revision/receipt from the owning GitHub release or Conductor record. Use an existing DOI archive route when a citable frozen release is needed.

Ordinary preparation, adapter development and local validation proceed under the programme's existing authority. External publication needs the actual target permission and compatible source rights; this plan creates no dataset, changes no companion repository and claims no publication or runtime integration.
