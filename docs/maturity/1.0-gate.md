# Version 1.0 maturity gate

Version 1.0 is a release decision, not a source-code milestone. Every required
domain must have current evidence, a named accountable reviewer and no
unaccepted critical blocker.

| Domain | Required evidence |
| --- | --- |
| Contracts | Compatibility report, migration fixtures and stable public API. |
| Compiler | Supported-platform build, formatting, lint, docs and test artefacts with committed lockfile. |
| Determinism | Replay, golden, property, metamorphic and crash-recovery tests. |
| Providers | Fixture proof plus authorised live receipts for every supported claim. |
| Methodology | PRESS/human calibration, seed-set results and independent evaluation. |
| Security | Threat-model review, dependency/secret/workflow scans, fuzzing, SBOM and attestations. |
| Interfaces | CLI install tests, MCP conformance/transcripts and facade parity. |
| Migration | Sourceright cutover and estate replacement evidence with rollback. |
| Usability | Accessibility and information-specialist usability findings resolved. |
| Operations | Health/SLO run, telemetry review, backup restore drill, incident exercise and support policy. |
| GitHub control plane | Observed remote repository, ruleset, issue/subissue and Project sync receipt. |
| Downstream compatibility | Exact-revision CiteWeft/Searchright/Sourceright canary receipts. |
| Access and tenancy | Authentication, scope, tenant, region, replay, abuse-budget and isolation evidence. |
| Backup, restore and incidents | Recovery-objective drill and post-exercise corrective-action closure. |
| SDK and adoption | Clean-environment examples, compatibility policy and public package evidence where claimed. |
| Pilots | Release-candidate rehearsal, pilot exit criteria and rollback exercise. |
| Registries | Public URLs, versions, dates and acceptance status for each claimed listing. |

The machine-readable dossier is `conductor/maturity-dossier.json`; the gap
register is `docs/maturity/gap-register.md`; and the final decision contract is
`docs/maturity/release-decision.md`. Any domain marked as a critical blocker
keeps the decision at `not_ready`. Closed GitHub issues, a populated Project,
source completeness or a signed tag cannot substitute for the required evidence.
