# Version 1.0 maturity gate

Version 1.0 is a release decision, not a source-code milestone. Every domain must
have current evidence and no unresolved critical blocker.

| Domain | Required evidence |
| --- | --- |
| Contracts | Compatibility report, migration fixtures and stable public API. |
| Compiler | Supported-platform build, formatting, lint, docs and test artefacts. |
| Determinism | Replay, golden, property, metamorphic and crash-recovery tests. |
| Providers | Fixture proof plus authorised live receipts for every supported claim. |
| Methodology | PRESS/human calibration, seed-set results and external evaluation. |
| Security | Threat-model review, dependency/secret/workflow scans, fuzzing and SBOM. |
| Interfaces | CLI install tests, MCP conformance/transcripts and facade parity. |
| Migration | Sourceright cutover and estate replacement evidence with rollback. |
| Usability | Accessibility and information-specialist usability findings resolved. |
| Operations | Signed reproducible release, support policy and registry evidence. |

The machine-readable dossier is `conductor/maturity-dossier.json`. A `false` or
`not_evidenced` domain blocks 1.0.
